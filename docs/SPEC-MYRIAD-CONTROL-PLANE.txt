PROMPT PARA CLAUDE — REDESIGN E EVOLUÇÃO FUNCIONAL COMPLETA DO MYRIAD

CONTEXTO GERAL

Você vai trabalhar no MYRIAD, um sistema interno que já funciona de verdade e NÃO é um mockup nem um projeto conceitual.

O MYRIAD é um sistema local para administrar uma operação de distribuição de conteúdo via celulares Android físicos conectados ao computador. Hoje ele é usado principalmente para Instagram. O sistema controla aparelhos físicos, contas, fila de postagens, horários, limites, aquecimento, publicação de Reels e carrosséis, coleta de views, watchdog de travamentos e conexão sem fio. Existe também uma “fábrica” separada que renderiza vídeos e entrega os arquivos prontos para o MYRIAD.

IMPORTANTE:
- O sistema já funciona.
- Não reescreva o motor inteiro sem necessidade.
- Não quebre a automação existente.
- Não transforme funções reais em mocks.
- Não crie botões falsos.
- Não esconda bugs com interface bonita.
- A prioridade é transformar o painel atual em uma ferramenta REAL DE ADMINISTRAÇÃO E CONTROLE.
- O painel deve refletir e controlar o estado real da operação.
- Antes de alterar qualquer coisa, inspecione o código atual, banco/arquivos de estado, rotas, workers, scheduler, watchdog, coleta de views e mecanismos de conexão.
- Reaproveite o máximo possível da arquitetura existente.
- Se precisar criar endpoints, serviços, migrations ou novas estruturas de dados, faça de forma compatível e organizada.
- Se alguma função visual exigir backend que ainda não existe, implemente o backend real correspondente quando for razoável. Não deixe um botão que apenas “parece funcionar”.
- Se houver alguma operação perigosa ou destrutiva, use confirmação explícita.

O PROBLEMA ATUAL

O painel atual parece mais um CRM / dashboard de leitura do que uma central de operação.

Hoje ele basicamente:
- mostra aparelhos;
- lista contas;
- mostra números de posts;
- mostra regras;
- lista arquivos da biblioteca;
- mostra instruções para conectar aparelho;
- despeja logs técnicos.

O problema é que eu consigo VER as coisas, mas quase não consigo ADMINISTRÁ-LAS.

Exemplos:
- vejo uma conta, mas não consigo facilmente pausar, editar, remover do rodízio ou excluir;
- vejo posts, mas não consigo controlar claramente fila, agenda, cancelamento, retry, publicação imediata, etc.;
- vejo vídeos da biblioteca, mas eles parecem arquivos numa pasta, não objetos administráveis;
- vejo o aparelho, mas ele é quase decorativo;
- vejo erros técnicos, mas não tenho uma camada operacional amigável;
- vejo regras de automação, mas a página parece quase read-only;
- “Conectar aparelho” é praticamente uma documentação, não um fluxo guiado real.

OBJETIVO PRINCIPAL

Transformar o MYRIAD de:

“painel que mostra o que existe”

para:

“CONTROL PLANE / CENTRAL DE COMANDO da operação”.

A regra de UX principal é:

SE EU VEJO ALGO NO MYRIAD, EU DEVO CONSEGUIR ADMINISTRÁ-LO DALI.

Para cada entidade importante, a interface deve responder:

1. O que está acontecendo agora?
2. O que vai acontecer depois?
3. O que eu posso fazer com isso?

FILOSOFIA DO PRODUTO

Não pense no MYRIAD como “um bot que posta Reels”.

Pense como:

MYRIAD = sistema operacional da operação de distribuição de conteúdo.

O aparelho é um worker físico.
A conta é um ativo operacional.
O post é um job.
A biblioteca é um inventário de conteúdo.
A automação define políticas e regras.
O analytics mede resultado.
Incidentes mostram problemas e recuperação.
A tela inicial mostra a saúde geral da operação.

REFERÊNCIA VISUAL / CONCEITUAL

A referência é o painel do Profit Phones.

Não quero uma cópia pixel a pixel.

Quero absorver a lógica:
- sensação de “central de comando”;
- aparelhos como workers visuais;
- alta densidade de informação útil;
- separação clara entre Devices, Accounts, Posts, Automation, Library etc.;
- operação parece viva;
- estado real é visível;
- escala fica evidente;
- interface serve para controlar, não só observar.

A estética atual do MYRIAD pode continuar escura, verde/preto, minimalista e séria, mas precisa parecer produto maduro.

A interface precisa parecer:
- operacional;
- técnica;
- organizada;
- confiável;
- viva;
- clara;
- sem excesso de cards inúteis;
- sem áreas vazias gigantes;
- sem “dashboard de template”.

1. VISÃO GERAL / CONTROL CENTER
==================================================

Criar uma página inicial real.

Objetivo:
abrir o MYRIAD e entender em 5 segundos como está toda a operação.

Topo:
- nome MYRIAD;
- estado global da operação;
- algo como:
  “Operação normal”
  “Atenção”
  “Operação pausada”
  “Falha crítica”

Indicadores principais:
- aparelhos online / total;
- contas ativas;
- posts publicados hoje / meta prevista;
- itens na fila;
- quantidade de conteúdo disponível;
- content buffer em dias;
- falhas/incidentes atuais;
- taxa de sucesso de postagens;
- views de hoje ou últimas 24h, se já houver dados confiáveis.

IMPORTANTE:
“Content buffer” é mais útil do que apenas “25 vídeos”.

Exemplo:
25 vídeos restantes
≈ 2,8 dias de conteúdo no ritmo atual

Calcular isso de forma real com base no ritmo de postagem das contas ativas.

Se não houver dados suficientes, mostrar claramente:
“Buffer indisponível — faltam dados de programação”.

Seção “Agora”:
mostrar o que cada aparelho está fazendo neste momento.

Exemplo:
Galaxy A15 #01
● aguardando próximo slot
Conta atual: @exemplo.corp
Próxima ação: Reel #172 às 09:30

Ou:
● POSTANDO
@exemplo.mind
reel172.mp4
etapa atual: Publicando

Seção “Próximas execuções”:
- próximos posts;
- horário;
- conta;
- conteúdo;
- aparelho previsto;
- status.

Seção “Atividade recente”:
exemplos:
- Reel publicado;
- views coletadas;
- aparelho reconectado;
- Instagram reiniciado pelo watchdog;
- post reagendado;
- erro resolvido automaticamente.

Seção “Saúde do sistema”:
- Scheduler;
- Worker;
- aparelho(s);
- ADB;
- Instagram;
- watchdog;
- coletor de views;
- fábrica, se houver integração detectável;
- banco/estado, se fizer sentido.

Não inventar saúde “verde”.
O estado precisa vir de sinais reais quando possível.
